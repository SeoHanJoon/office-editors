# Step 시작: Step $ARGUMENTS

## 1. Step 내용 확인

- `README.md`의 "3. Step 목록" 표에서 Step $ARGUMENTS 행을 읽는다. (대상, 할 일, 완료 기준)
- 앞 Step이 끝났는지(✅) 확인한다. 안 끝났으면 사용자에게 알리고 계속할지 묻는다.
- `adr/`의 기존 ADR을 훑어서 이번 Step이 따라야 할 이전 결정을 파악한다.

## 2. 브랜치 만들기

- 작업 트리가 깨끗한지 `git status`로 확인한다. 변경이 있으면 멈추고 사용자에게 묻는다.
- `main`에서 `step-<번호>-<짧은-영문-이름>` 브랜치를 만든다. (예: `step-2-excel-grid`)

## 3. 결정할 것 뽑기

이 Step에서 **사람이 결정해야 하는 설계 선택**을 목록으로 만든다. 각 항목에 선택지 2~3개와 장단점을 짧게 붙인다.

- 예: 셀 저장 구조(2차원 배열 vs Map), 수식 AST 형태, 테스트 도구 선택
- 결정은 사용자가 한다. 추천은 해도 되지만 사용자가 고르기 전에 구현하지 않는다.
- 결정되면 `/adr`로 기록한다.

## 4. 작업 계획

아래 형식으로 사용자에게 보여주고 확인받은 뒤 구현을 시작한다.

```
Step N: <제목>
완료 기준: <README의 완료 기준>

결정할 것:
  1. ...

작업 순서:
  1. ...

테스트:
  - 단위 테스트: ...
  - 브라우저 테스트: ... (화면 변경이 있을 때만)
```

## 지킬 것

- README의 "4. 테스트 방식"과 "5. 폴더 구조" 규칙을 따른다. (`excel`, `docs`, `ppt`는 서로 import하지 않음)
- Excel은 핵심 로직(데이터 구조, 수식, 렌더링)을 라이브러리 없이 직접 구현한다. Docs·PPT는 라이브러리를 써도 된다.
- 커밋은 사용자가 요청할 때만 한다.
