# ADR 작성

## 1. 번호와 파일 이름

- `adr/`에서 가장 큰 번호를 찾아 +1 한다. 처음이면 `0001`.
- 파일 이름: `adr/<4자리 번호>-<짧은-영문-kebab-case>.md` (예: `adr/0003-cell-storage.md`)

## 2. 내용

README의 "ADR이란?" 형식을 그대로 쓴다.

```markdown
# 0003. 셀 데이터 저장 구조

- 상태: 채택
- 날짜: YYYY-MM-DD
- 관련 Step: Step 2

## 배경
어떤 문제가 있었나?

## 선택지
- A안: 장점 / 단점
- B안: 장점 / 단점

## 결정
무엇을 골랐고, 왜 골랐나?

## 결과
이 결정으로 좋아지는 점과 감수해야 하는 점
```

작성 규칙:

- **결정은 사용자의 것이다.** 사용자가 고른 선택과 그 이유를 적는다. 사용자가 아직 고르지 않았으면 상태를 `제안`으로 두고 결정 칸에 추천안을 "추천:"으로 적은 뒤 사용자에게 확인받는다.
- 쉬운 말로 짧게 쓴다. 한 섹션에 3~5줄이면 충분하다.
- 숫자 근거가 있으면 넣는다. (예: "10만 행 기준 메모리 40MB vs 400MB")
- 날짜는 오늘 날짜를 쓴다.

## 3. 기존 결정을 바꿀 때

- 이전 ADR을 지우거나 고쳐 쓰지 않는다.
- 새 ADR을 만들고, 이전 ADR의 상태를 `폐기 (→ 00NN)`로 바꾼다.

## 4. README 연결

- README "3. Step 목록" 표에서 관련 Step 행의 ADR 칸에 링크를 넣는다.
  - 처음이면 `예정`을 `[0003](adr/0003-cell-storage.md)`로 바꾼다.
  - 이미 링크가 있으면 `, `로 이어 붙인다.
