# Step 마무리

## 1. 어떤 Step인지 확인

- 현재 브랜치 이름(`step-<번호>-...`)으로 Step 번호를 알아낸다.
- README "3. Step 목록"에서 그 Step의 완료 기준을 읽는다.

## 2. 검사 실행

아래를 실행하고 결과를 그대로 보고한다. 실패하면 여기서 멈추고 원인을 보고한다.

```bash
pnpm typecheck
pnpm test
pnpm e2e        # 브라우저 테스트가 있는 Step만
pnpm bench      # Step 5 이후, 성능 관련 변경이 있을 때만
```

- 벤치마크를 돌렸으면 README "Excel 성능 목표" 표의 측정값 칸을 채운다.

## 3. 완료 기준 확인

- README의 완료 기준을 하나씩 확인하고 표로 보고한다. (항목 / 충족 여부 / 근거)
- 충족하지 못한 항목이 있으면 README를 체크하지 않고 사용자에게 알린다.

## 4. ADR 점검

- `git diff main...HEAD`와 이번 대화를 보고, 이 Step에서 내린 설계 결정 중 ADR이 없는 것을 찾는다.
  - ADR이 필요한 것: 데이터 구조, 공개 인터페이스, 라이브러리 선택, 성능을 위해 구조를 바꾼 것
  - 필요 없는 것: 변수 이름, 작은 리팩터링
- 빠진 것이 있으면 사용자에게 목록을 보여주고 `/adr`로 작성한다.
- 이 Step에 ADR이 하나도 없으면 반드시 사용자에게 확인한다.

## 5. README 갱신

- Step 목록 표의 해당 행 Step 칸에 ✅를 붙인다. (예: `**2** ✅`)
- ADR 칸에 이 Step의 ADR 링크가 모두 있는지 확인한다.
- 이번 Step 때문에 README의 다른 내용(폴더 구조, 실행 명령)이 바뀌었으면 함께 고친다.

## 6. 커밋

- 2단계 검사가 모두 통과했을 때만 커밋한다. 실패했으면 커밋하지 않고 결과를 보고한다.
- 마무리에서 바뀐 것(README, ADR, 남은 코드 변경)을 커밋한다. 메시지는 `docs(step-N): ...`처럼 쓴다.
- `git status`로 커밋되지 않은 변경이 남지 않았는지 확인한다.

## 7. 마무리 보고

- 바뀐 파일 목록과 다음 할 일을 짧게 보고한다.
- 화면에 영향이 있는 Step이면 PR 전에 `pnpm e2e:record`로 영상을 녹화하라고 안내한다.
- PR을 올리려면 `/pr`을 쓰라고 안내한다. push와 PR은 하지 않는다.
