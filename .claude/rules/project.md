# 프로젝트 공통 규칙

## 작업 방식

- 작업은 README "3. Step 목록"의 Step 단위로 한다. 현재 Step 범위 밖의 기능은 만들지 않고, 필요해 보이면 사용자에게 제안만 한다.
- **설계 결정은 사용자가 한다.** 데이터 구조, 공개 인터페이스, 라이브러리 선택, 폴더 구조 변경은 선택지와 장단점을 보여주고 사용자가 고른 뒤에 구현한다. 결정은 `adr/`에 기록한다.
- 이미 채택된 ADR과 다르게 구현해야 하면 멈추고 사용자에게 알린다.
- 커밋, push, PR은 사용자가 요청할 때만 한다.

## 설명 방식

- 사용자에게는 한국어로, 쉬운 말로 설명한다. 전문 용어를 쓰면 한 줄로 뜻을 붙인다.

## 패키지 의존 방향

아래 방향으로만 import한다. 새 의존이 필요하면 사용자에게 먼저 묻는다.

| 패키지 | import 가능 |
|---|---|
| `packages/command-core` | 없음 (외부 라이브러리도 쓰지 않음) |
| `packages/ui` | React |
| `packages/excel`, `packages/docs`, `packages/ppt` | `command-core`, `ui` |
| `apps/web` | 모든 패키지 |

- `excel`, `docs`, `ppt`는 서로 import하지 않는다. 공통으로 필요한 것은 `command-core`나 `ui`로 옮긴다.

## 완료 조건

- 작업이 끝났다고 말하기 전에 `pnpm typecheck`와 `pnpm test`를 실행하고, 실패하면 결과를 그대로 보고한다. (Step 0 이후)
- 버그를 고치면 그 버그를 다시 잡는 테스트를 추가한다.
