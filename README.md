# Office Editors

웹에서 동작하는 **Excel · Docs · PPT** 에디터를 하나의 저장소(모노레포)에서 만드는 프로젝트입니다.

- **Excel은 깊게** — 수식 계산, 대용량 표 그리기 같은 핵심을 라이브러리 없이 직접 구현합니다.
- **Docs · PPT는 가볍게** — 검증된 라이브러리를 사용하고, 기본 편집 기능만 만듭니다.

---

## 1. 무엇을 만드나

| 에디터 | 깊이 | 직접 구현하는 것 | 가져다 쓰는 것 |
|---|---|---|---|
| **Excel** | 깊게 | 셀 데이터 구조, 수식 계산기, 표 그리기(Canvas), 복사/붙여넣기 | 거의 없음 |
| **Docs** | 가볍게 | 저장/불러오기, 공통 기능 연결 | Tiptap (문서 에디터 라이브러리) |
| **PPT** | 가볍게 | 슬라이드 목록, 도형/텍스트 배치 | 일반 HTML(DOM) |

세 에디터가 **공통으로 쓰는 부분**(실행 취소/다시 실행 등)은 한 번만 만들어서 함께 사용합니다.

---

## 2. 진행 방식

작업은 **Step 단위**로 진행합니다. 각 Step은 이렇게 끝납니다.

1. 기능을 구현한다.
2. 테스트가 통과한다.
3. 그 Step에서 내린 중요한 결정을 **ADR**로 남긴다.
4. 아래 진행 표에 체크한다.

### ADR이란?

ADR(Architecture Decision Record)은 **"왜 이렇게 만들었는지"를 적어두는 짧은 문서**입니다.
나중에 "이거 왜 이렇게 했지?"라는 질문에 답하기 위한 기록입니다.

- 위치: [`adr/`](adr/) 폴더
- 파일 이름: `번호-제목.md` (예: `0001-monorepo-tooling.md`)
- 한 Step에서 결정이 여러 개면 ADR도 여러 개 만들어도 됩니다.

ADR은 아래 형식으로 짧게 씁니다.

```markdown
# 0001. 제목

- 상태: 제안 / 채택 / 폐기
- 날짜: YYYY-MM-DD
- 관련 Step: Step 0

## 배경
어떤 문제가 있었나?

## 선택지
- A안: 장점 / 단점
- B안: 장점 / 단점

## 결정
무엇을 골랐고, 왜 골랐나?

## 결과
이 결정으로 좋아지는 점과 감수해야 하는 점
```

### Step 7 범위 (Excel 오른쪽 클릭 메뉴)

| 메뉴가 뜨는 곳 | 항목 |
|---|---|
| 행 머리글 | 잘라내기, 복사, 붙여넣기 / 위에 행 넣기, 아래에 행 넣기 / 행 삭제 / 내용 지우기 |
| 열 머리글 | 잘라내기, 복사, 붙여넣기 / 왼쪽에 열 넣기, 오른쪽에 열 넣기 / 열 삭제 / 내용 지우기 |
| 셀 | 잘라내기, 복사, 붙여넣기 / 내용 지우기 / 행 위·아래에 넣기, 열 왼쪽·오른쪽에 넣기 / 행 삭제, 열 삭제 (고른 셀이 걸친 줄 전체) |

- 여러 줄을 골랐으면 고른 줄 수만큼 넣는다. (예: 3행을 골랐으면 "위에 행 3개 넣기")
- 오른쪽 클릭한 곳이 선택 안이면 선택을 그대로 두고, 밖이면 그 셀·줄로 선택을 옮긴 뒤 메뉴를 연다.
- 메뉴는 Esc·바깥 클릭·스크롤로 닫히고, ↑↓·Enter로도 고를 수 있다. Shift+F10으로도 연다. 항목 옆에 단축키를 보여준다.
- 할 수 없는 항목은 흐리게 보여준다. (예: 시트를 비우게 되는 삭제)
- 전체 선택: 왼쪽 위 모서리 클릭, Ctrl/Cmd+A. 줄 선택: Shift+Space(행), Ctrl+Space(열).
- 시작할 때 정할 것: 메뉴에서 클립보드를 읽고 쓰는 방법(브라우저 권한), 메뉴 코드를 둘 곳(`excel` 또는 `ui`), Mac에서 Ctrl+Space가 한/영 전환과 겹치는 문제. [ADR 0026](adr/0026-insert-delete-rows-columns.md)에서 "오른쪽 클릭 메뉴 없음"으로 정한 것을 바꾸므로 새 ADR을 쓴다.

### Step 8 범위 (크기 조절, 셀 안 줄바꿈)

- 열 머리글·행 머리글의 경계선을 끌어 너비·높이를 바꾼다. 여러 줄을 골랐으면 고른 줄이 모두 같은 크기가 된다.
- 경계선을 두 번 클릭하면 내용에 맞게 자동으로 맞춘다.
- 셀 안 줄바꿈: 입력 중 Alt+Enter(Mac은 Option+Enter)로 줄을 바꾼다. 입력창도 내용에 맞게 커진다.
- 줄바꿈이 든 셀은 여러 줄로 그리고, 그 행의 높이는 가장 긴 셀에 맞게 저절로 늘고 준다.
  - 사용자가 높이를 직접 바꾼 행은 저절로 바뀌지 않는다. (Excel과 같음) 경계선을 두 번 클릭하면 다시 자동이 된다.
- 크기 바꾸기도 undo 한 번에 되돌아간다. 행·열을 넣고 지우면 크기도 같이 옮겨진다.
- 10만 행 시트에서도 Step 5 성능 목표를 지킨다. 행마다 높이가 달라지므로 "y 위치 → 몇 번째 행"을 빠르게 찾는 방법을 새로 정해야 한다.

### Step 9 범위 (채우기 핸들)

- 선택 범위 오른쪽 아래의 작은 네모를 끌어 위·아래·왼쪽·오른쪽으로 채운다.
- 채우는 규칙 (Excel과 같게)
  - 숫자 한 칸: 같은 값을 복사한다. 숫자 두 칸 이상(1, 3): 같은 간격으로 이어간다. (5, 7, …)
  - 끝에 숫자가 붙은 글자("항목1"): 숫자만 1씩 늘린다.
  - 요일·월("월", "화" / "1월", "2월"): 목록 순서대로 이어간다.
  - 수식: 붙여넣기처럼 `$`가 없는 참조만 옮긴 만큼 따라간다.
- 원래 범위 안쪽으로 끌어 줄이면 줄인 칸을 지운다.
- 네모를 두 번 클릭하면 옆 열에 데이터가 있는 곳까지 아래로 채운다.
- 함께 넣는 단축키: Ctrl+D(아래로 채우기), Ctrl+R(오른쪽으로 채우기), Ctrl+Enter(입력한 값을 고른 범위 전체에 넣기).

### Step 10 범위 (툴바, 수식 입력줄, 셀 서식)

- 표 위에 툴바와 수식 입력줄을 둔다.
  - 수식 입력줄: 왼쪽에 이름 상자(지금 셀 주소, 주소를 입력하면 이동), 오른쪽에 셀에 든 글자(수식이면 수식)를 보여주고 여기서도 고칠 수 있다.
  - 툴바: 실행 취소·다시 실행 버튼과 아래 서식 버튼. 지금 고른 셀의 서식이 버튼 상태에 보인다.
- 넣는 서식
  - 글자: 굵게·기울임·밑줄·취소선 (Ctrl+B/I/U), 글자 크기, 글자색
  - 칸: 채우기 색, 테두리 (모두·바깥쪽·없음 등 자주 쓰는 모양만)
  - 정렬: 가로(왼쪽·가운데·오른쪽), 세로(위·가운데·아래), 자동 줄바꿈 (켜면 열 너비에 맞춰 줄을 바꾸고 Step 8의 행 높이 자동 맞춤에 반영)
  - 숫자 형식: 일반·숫자(천 단위 쉼표)·통화(₩)·백분율, 소수 자릿수 늘리기·줄이기
  - 서식 지우기
- 서식은 복사·붙여넣기(앱 안), 채우기 핸들, 행·열 넣기(바로 위·왼쪽 줄의 서식을 따름), undo를 모두 따라간다.
- 10만 행 시트에서 열 전체에 서식을 줘도 느려지지 않아야 한다. 서식을 셀마다 저장할지, 행·열·범위 단위로 저장할지 시작할 때 정한다.
- 이번에 넣지 않는 것 (나중 후보): 셀 병합, 날짜·시간 형식(날짜 입력 알아보기 포함), 조건부 서식, 서식 복사 붓, 글꼴 종류 바꾸기, 셀·표 스타일, Excel에서 서식째 붙여넣기(HTML 읽기), 파일 저장·불러오기

### Excel 성능 목표 (Step 5)

| 상황 | 목표 | 측정값 |
|---|---|---|
| 10만 행 × 50열 스크롤 | 끊김 없이(60fps) | 60fps, 밀린 프레임 0 (세로 천천히·빠르게, 가로 모두), 그리기 최대 0.0039초 |
| 연결된 셀 1만 개 다시 계산 | 0.05초 이내 | 0.0081초 |
| 큰 `SUM` 수식이 있는 시트에서 셀 하나 수정 | 0.016초 이내 | 0.0044초 (`=SUM(A1:A100000)`) |
| 10만 행 시트(수식 20만 개) 첫 화면 — 셀까지 그려짐 | 0.5초 이내 | 0.27~0.42초 (수식 계산 완료 1.3~1.5초, 그동안 "…" 표시) |

> Step 10: 서식이 있는 한 화면 그리기는 0.55ms다. (서식이 없으면 0.41ms로 그대로) 10만 행 열 전체에 굵게 주기 + 되돌리기는 0.02ms(열 서식 하나), 열 전체 자동 줄바꿈의 행 높이 다시 재기는 0.2초다. 스크롤 60fps와 첫 화면(0.28~0.45초)은 그대로다. ([ADR 0034](adr/0034-cell-format-storage.md), [ADR 0036](adr/0036-wrap-text-row-height.md))

> Step 9: 채우기 핸들을 그려도 한 화면 그리기는 평균 0.44ms로 그대로다. 10만 행 성적표에서 핸들을 두 번 눌러 열 하나를 채우고 되돌리기는 숫자 0.38초, 수식 0.58초다. (목표 없음, [ADR 0033](adr/0033-fill-handle.md))

> Step 8: 첫 화면이 Step 7보다 약 0.05초 늘었다. (행 높이 자동 맞춤용 줄 수 세기 14ms, 개발 서버는 React가 화면을 두 번 만들어 두 번 돈다) 행마다 높이가 다른 10만 행 한 화면 그리기 0.26ms, 줄 크기 색인 다시 만들기 최대 3.6ms ([ADR 0032](adr/0032-line-size-index.md)).

> Step 6: 같은 시트 맨 위에 행 하나 넣기는 목표 없이 잰다. 한 번에 약 0.5초 (넣기 + 되돌리기 1.03초, [ADR 0028](adr/0028-engine-structure-shift.md)).

> 2026-10-01(Step 9 마무리), Apple M1 Mac, `pnpm bench` 기준. 스크롤은 개발 서버의 Chromium(1280×720)에서 쟀다. 측정 방법은 [ADR 0022](adr/0022-performance-measurement.md) 참고.

## 4. 테스트 방식

Excel은 촘촘하게, Docs · PPT는 핵심 흐름만 테스트합니다.

### 단위 테스트 (Vitest)

브라우저 없이 함수와 데이터만 확인합니다. 테스트 대부분을 여기에 둡니다.

| 대상 | 확인하는 것 |
|---|---|
| `command-core` | undo/redo, 연속 입력 합치기, 여러 편집을 한 번에 되돌리기 |
| Excel 수식 파서 | 수식을 올바르게 읽는지, 잘못된 수식에 에러를 내는지 |
| Excel 수식 계산 | 함수별 결과값, `#DIV/0!` 같은 에러 값 |
| 의존성 그래프 | 필요한 셀만 다시 계산하는지, 순환 참조를 잡는지 |
| 행·열 삽입 | 행을 끼우면 `=A5`가 `=A6`으로 바뀌는지 |

### 정답 비교 테스트 (Excel 수식)

같은 시트를 [HyperFormula](https://hyperformula.handsontable.com/)로도 계산해 결과가 같은지 비교합니다.
HyperFormula는 테스트에서 정답을 얻는 데만 쓰고, 실제 코드에는 넣지 않습니다.

### 브라우저 테스트 (Playwright) + 영상 녹화

사용자가 실제로 하는 동작을 브라우저에서 확인하고, **그 과정을 영상으로 녹화**해 PR에 첨부합니다.

- Excel: 셀 입력, 방향키 이동, 복사/붙여넣기, 한글 입력
- Docs · PPT: 입력, 서식 적용, undo

Excel 표는 Canvas로 그리기 때문에 결과는 화면이 아니라 내부 데이터를 꺼내서 확인합니다.

```bash
pnpm e2e          # 브라우저 테스트 실행 (녹화 없음)
pnpm e2e:record   # 녹화하면서 실행 → recordings/ 폴더에 영상(.webm) 저장
```

**PR 올릴 때:** `/pr`이 브라우저 테스트를 녹화해 `gh --attach`로 PR 본문에 넣습니다. PR에서 바로 재생됩니다. (GitHub CLI v2.99.0 이상 필요)
기존 화면을 바꾼 PR이면 바뀌기 전(as-is, `main`)과 후(to-be)를 나란히 올리고, 새 기능이면 to-be만 올립니다.

### 성능 측정 (Step 5부터)

`pnpm bench` 한 번으로 모두 잽니다. 결과는 표로만 보여주고, 목표를 넘어도 실패하지 않습니다.

- 재계산 속도·처음 열기: `packages/excel/src/*.bench.ts` (vitest bench)
- 스크롤 60fps: 세 가지로 잽니다.
  - ① 프레임 간격: 브라우저에서 스크롤하며 프레임 사이 시간을 잼 (`apps/web/perf/`)
  - ② Chrome 성능 기록: 화면에 나간 프레임과 버린 프레임을 셈 (`apps/web/perf/`)
  - ③ 그리기 시간만: 브라우저 없이 표 그리기 코드의 시간만 잼 (`packages/excel/src/render.bench.ts`)
- `pnpm test`의 대용량 테스트는 결과가 맞는지와 목표의 약 10배 안에 끝나는지만 봅니다.

### 규칙

- 테스트 파일은 코드 옆에 둡니다. (예: `parser.ts` 옆에 `parser.test.ts`)
- 모든 Step의 완료 기준에는 "`pnpm test` 통과"가 포함됩니다.
- 버그를 고치면 그 버그를 잡는 테스트를 함께 추가합니다.

apps/
  web/            화면 (Next.js) — 세 에디터를 여기서 띄움

## 6. 실행 방법

Node.js 24.21 (LTS, `.nvmrc` 참고)과 pnpm이 필요합니다. (Step 0 완료 후 사용 가능)

```bash
nvm use          # .nvmrc의 Node 버전으로 전환
pnpm install     # 설치
pnpm --filter @office/web exec playwright install chromium  # 브라우저 테스트용 Chromium 설치 (처음 한 번)
pnpm dev         # 개발 서버 실행
pnpm test        # 단위 테스트
pnpm e2e         # 브라우저 테스트
pnpm e2e:record  # 브라우저 테스트 + 영상 녹화
pnpm typecheck   # 타입 검사
pnpm bench       # 성능 측정 (Step 5 이후)
```
