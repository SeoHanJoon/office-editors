# 0014. 셀 입력창: 활성 셀 위에 늘 떠 있는 textarea

- 상태: 채택
- 날짜: 2026-09-30
- 관련 Step: Step 3

## 배경
표는 Canvas라 글자를 받을 수 없어서 셀 위에 DOM 입력창을 띄운다.
한글은 입력기가 자모를 조합(ㅎ → 하 → 한)하는데, 조합이 시작될 때 포커스가 입력창에 없으면 첫 자모가 사라지거나 두 번 들어간다.
사용자 조건: **한글 첫 글자가 사라지거나 두 번 들어가는 버그는 절대 안 된다.**

## 선택지
- A안 입력창을 항상 활성 셀 위에 투명하게 두고 포커스를 거기에 둔다 (Google Sheets 방식): 입력기가 처음부터 입력창에서 조합을 시작해 첫 글자가 구조적으로 안전 / 선택이 움직일 때 입력창도 옮겨야 하고, 이동 키를 입력창에서 받아야 함
- B안 표에 포커스를 두고 글자 키가 오면 입력창을 만들어 포커스를 옮긴다: 단순 / 첫 자모가 입력창이 생기기 전에 조합되어 사라지거나 두 번 들어감 (Handsontable이 오래 겪은 버그)
- 입력창 요소: `<textarea>`(나중에 Alt+Enter 줄바꿈 가능) / `<input>`(속도 같음, 한 줄만) / contenteditable(더 무겁고 조합 버그가 많음)

## 결정
A안 + `<textarea>`. 사용자가 textarea 성능을 물었고, 아래 이유로 문제가 없다고 보고 골랐다.
- 시트 전체에 입력창은 하나다. 셀을 옮기면 `transform`만 바꾼다. 글자를 칠 때 Canvas를 다시 그리지 않고 글자가 넘칠 때만 너비를 늘린다.
- 입력창은 스크롤 영역 밖(`overflow: clip` 틀 안)에 있어서 표 스크롤과 상관없고, 브라우저가 커서를 보이게 하려고 화면을 멋대로 스크롤하지 않는다. 포커스는 `preventScroll`로 준다.

동작 규칙:
- 입력 중이 아닐 때 입력창은 투명하고 마우스를 아래 표로 흘려보낸다. value는 늘 비어 있다.
- `compositionstart`나 글자 `input`이 오면 그때 입력창을 보이게만 한다. **조합 중에는 value를 건드리지 않는다.**
- 조합 중인 키(`isComposing`, 조합을 끝내는 Enter 포함)는 무시하고, 조합이 끝난 뒤 오는 키로 처리한다.
- 조합 중에 다른 셀을 클릭하면 포커스가 안 옮겨져 조합이 안 끝나므로, 입력창 포커스를 잠깐 뺐다 돌려서 브라우저가 조합을 확정하게 한 뒤 값을 읽는다.
- 입력 상태는 Excel처럼 둘이다. 글자로 시작한 "enter"(방향키가 확정하고 이동), F2·더블클릭으로 시작한 "edit"(방향키가 커서 이동). F2로 서로 바꾼다.

## 결과
- 한글 입력은 브라우저 테스트에서 Chrome의 실제 조합 이벤트(CDP `Input.imeSetComposition`)로 확인한다. 조합 중 클릭 처리를 빼면 이 테스트가 실패하는 것도 확인했다.
- CDP 조합은 브라우저 안에서만 일어나서 운영체제 입력기와 똑같지는 않다. Windows 한글 입력기와 Safari의 Enter 순서는 자동 테스트로 확인하지 못했다. 사람이 직접 확인해야 한다.
- 입력창이 늘 포커스를 가지므로 표의 키 처리도 모두 입력창에서 받는다. 스크롤 영역이 포커스를 받으면 입력창으로 돌려준다.
- 입력 중이 아닐 때 붙여넣기·줄바꿈 등은 입력창에서 막는다. 붙여넣기는 Step 6에서 만든다.
- Alt+Enter 줄바꿈, Ctrl+Enter 범위 채우기는 아직 없다. (셀 안 여러 줄 그리기가 먼저 필요)
