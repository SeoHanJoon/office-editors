# 0003. 테스트 실행 구성: Vitest는 패키지별, Playwright는 apps/web

- 상태: 채택
- 날짜: 2026-09-30
- 관련 Step: Step 0

## 배경
단위 테스트가 여러 패키지에 흩어진다. `pnpm test`가 이를 어떻게 모아 돌릴지,
브라우저 테스트와 영상 녹화를 어디에 둘지 정해야 한다.

## 선택지
- A안 Turbo가 패키지별로 `vitest run` 실행: 바뀐 패키지만 다시 테스트(캐시), typecheck와 같은 방식 / 결과가 패키지별로 나뉘어 출력
- B안 루트 Vitest projects로 한 번에 실행: 설정 한 곳, 출력 하나 / Turbo 캐시를 못 써서 매번 전체 실행

## 결정
A안. 수식 엔진 테스트가 많아질수록 캐시 이점이 크고, typecheck와 방식이 같아 이해하기 쉽다.
- 패키지는 Vitest 기본 설정으로 충분해 설정 파일을 두지 않는다. `apps/web`만 `e2e/`를 제외하는 설정을 둔다.
- Playwright는 `apps/web/e2e/`에 두고 Chromium만 쓴다. 테스트 서버는 `next dev`로 띄운다.
- `pnpm e2e:record`는 `RECORD=1`로 실행되어 영상 녹화를 켜고, 저장소 루트 `recordings/`에 저장하며, 사람이 보기 좋게 동작 사이를 0.5초씩 늦춘다(`slowMo`).

## 결과
- 한 패키지만 고치면 그 패키지와 `apps/web`만 다시 테스트된다.
- 패키지별 출력이라 전체 요약이 한눈에 보이지 않는다. (Turbo가 성공/실패 개수만 합쳐 보여준다)
- `recordings/`는 실행할 때마다 비워지므로 필요한 영상은 PR에 올리기 전에 옮겨 둔다.
