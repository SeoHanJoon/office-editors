# 0008. 셀 데이터 저장 구조와 셀 주소

- 상태: 채택
- 날짜: 2026-09-30
- 관련 Step: Step 2

## 배경
Excel 시트의 셀 값을 어떻게 담을지, 셀 위치를 코드에서 어떻게 부를지 정해야 한다.
Step 5에서 10만 행 × 50열(500만 칸)을 다루지만 실제로 값이 있는 칸은 그보다 훨씬 적다.
Excel 한 시트의 최대 크기는 1,048,576행 × 16,384열이다.

## 선택지
- 저장 구조
  - A안 숫자 키 Map (`행 × 16384 + 열`): 빈 칸은 메모리를 안 씀, 찾기가 빠름 / 키만 보고 주소를 알기 어려움
  - B안 문자열 키 Map (`"A1"`): 읽기 쉬움 / 찾을 때마다 문자열을 만들어 스크롤 성능에 불리
  - C안 행별 Map 중첩: 한 행을 모아 보기 쉬움 / Map이 두 겹이라 코드·메모리가 늘어남
  - D안 2차원 배열: 가장 단순하고 빠름 / 빈 칸도 자리를 차지해 500만 칸이면 메모리 부담
- 셀 주소: `{row, col}` 0부터 / `{row, col}` 1부터 / `"A1"` 문자열
- 셀에 저장하는 값: 입력한 글자 그대로 / 타입 있는 값(number, string, boolean)

## 결정
- 저장은 A안. 값이 있는 셀만 `Map<number, string>`에 넣는다. 키에 곱하는 수는 시트 열 수가 아니라 Excel 최대 열 수(16,384)라서, 열을 넣고 빼도(Step 6) 다른 셀의 키가 섞이지 않는다. 최대 키는 약 172억으로 JS 숫자가 정확히 다루는 범위 안이다.
- 주소는 `{row, col}` 0부터 (A1 = `{row: 0, col: 0}`). 배열·픽셀 계산과 맞아 코드가 단순하다. `toA1`, `parseA1`, `rangeToA1`로 `"A1"`과 바꾼다.
- 셀에는 사용자가 친 글자를 그대로 저장한다 (`"12"`, `"=A1+1"`). 빈 문자열은 빈 셀이다. 숫자인지는 그릴 때 간단히 판단해 오른쪽 정렬만 한다. 계산값은 수식 Step(Step 4)에서 따로 둔다.

## 결과
- 빈 칸이 많은 큰 시트도 값이 있는 셀 수만큼만 메모리를 쓴다.
- 행·열 삽입(Step 6) 때는 뒤쪽 셀의 키를 모두 다시 계산해야 한다. (값이 있는 셀 수에 비례)
- Excel 화면 번호(1부터)와 1씩 차이가 나므로 화면·테스트에는 항상 `"A1"` 형태로 보여준다.
- 이번 Step의 `Sheet`에는 값을 바꾸는 메서드가 없다. 셀 입력 Step(Step 3)에서 Command와 함께 추가한다.
