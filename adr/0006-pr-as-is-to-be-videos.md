# 0006. PR 영상은 상황에 따라 as-is와 to-be를 나란히 올린다

- 상태: 채택
- 날짜: 2026-09-30
- 관련 Step: Step 0

## 배경
0005로 PR 본문에 영상이 바로 보이게 됐지만, 바뀐 뒤(to-be) 영상만 있어서 무엇이 달라졌는지 한눈에 비교하기 어렵다.
바뀌기 전(as-is) 영상은 base 브랜치 코드로 따로 녹화해야 한다.

## 선택지
- as-is에서 돌릴 테스트
  - A안 이 PR의 테스트 파일을 base 코드 위에서 실행: 같은 시나리오로 비교됨, 버그 수정이면 as-is에서 버그가 보임 / 새 기능 테스트는 as-is에서 실패 화면만 나옴
  - B안 base의 테스트 파일을 그대로 실행: 항상 base에서 통과함 / PR에서 테스트를 바꾸면 시나리오가 달라 비교가 안 됨
- 배치
  - 표로 나란히: 한눈에 비교 / 화면이 좁으면 영상이 작아짐
  - 위아래로: 영상이 큼 / 스크롤하며 비교해야 함

## 결정
A안 + 표로 나란히. 비교가 목적이므로 같은 시나리오가 중요하다. 표 칸 안에서도 영상 플레이어로 보이는 것을 PR #1에서 확인했다.
- `.claude/skills/pr/record-as-is.sh`가 base를 git worktree(임시 작업 폴더)로 꺼내 PR의 `apps/web/e2e/`를 덮어쓰고 녹화한다. 결과는 `recordings/as-is/`.
- 이미 떠 있는 서버를 재사용하지 않도록 `CI=1`, `E2E_PORT=3100`으로 띄운다. (`playwright.config.ts`가 `E2E_PORT`를 읽는다)
- 테스트마다 상황을 판단한다: 화면 변경 없음 → 영상 없음 / 새 기능 → to-be만 / 기존 동작 변경 → as-is + to-be.

## 결과
- 리뷰어가 PR에서 바뀌기 전과 후를 나란히 재생해 볼 수 있다.
- as-is 녹화는 base 의존성 설치와 서버 시작 때문에 1분 안팎 더 걸린다.
- 새 기능 테스트는 as-is를 만들지 않도록 사람이(또는 `/pr`이) 판단해야 한다.
- base에 `E2E_PORT` 설정이 없으면 3000번 포트를 쓴다. 이때 다른 서버가 3000번을 쓰고 있으면 as-is 녹화가 실패한다.
