# 0031. 행 높이·열 너비: Sheet에 저장할 것과 화면이 계산할 것

- 상태: 채택
- 날짜: 2026-10-01
- 관련 Step: Step 8

## 배경
Step 8에서 행 높이·열 너비를 바꿀 수 있게 하고, 줄바꿈이 든 셀이 있으면 행 높이가 저절로 늘고 줄게 한다.
크기 데이터를 어디에 둘지, 어떤 단위로 둘지, 자동 높이를 무엇으로 정할지 골라야 한다.
사용자는 **나중에 서버에 저장하고 불러오는 기능**이 붙는 것을 기준으로 다시 따져 달라고 했다.
그래서 먼저 데이터를 둘로 나눴다.
- 문서 데이터 (저장한다): 셀 글자, 사용자가 직접 바꾼 크기
- 다시 만들 수 있는 것 (저장하지 않는다): 자동 행 높이, 위치 찾기 색인(ADR 0032). 수식 계산값을 저장하지 않는 것과 같다.

## 선택지
- 크기를 둘 곳
  - A안 직접 바꾼 크기는 `Sheet`, 자동 높이는 화면 쪽 계산: 저장할 것이 한 객체에 모이고, 행·열 넣기/지우기와 undo가 셀과 같은 곳에서 크기를 옮긴다. / `Sheet`가 하는 일이 늘어난다.
  - B안 앱이 만드는 별도 `SheetSizes` 객체 (엔진과 같은 방식): `Sheet`는 그대로다. / 저장·불러오기 때 두 객체를 맞춰야 하고, `StructureCommand`가 이 객체도 알아야 한다.
  - C안 `GridView` 안: 가장 간단하다. / 화면이 없으면 크기를 다룰 수 없어 서버에서 시트를 저장·처리하지 못한다.
- 자동 행 높이 기준
  - A안 입력한 글자의 줄바꿈 수: 불러온 직후 셀 글자만으로 높이가 정해진다. / 수식 결과의 줄바꿈은 한 줄로 그린다.
  - B안 보이는 값(수식 결과 포함): 수식 결과도 여러 줄이다. / 나눠서 계산하는 동안(ADR 0024) 계산이 끝날 때마다 높이가 바뀌어 화면이 흔들린다.
- 단위
  - A안 화면 CSS px: 코드 어디서나 그대로 쓴다. / `.xlsx`와 주고받을 때 바꿔야 한다.
  - B안 Excel 단위 (행은 pt, 열은 "숫자 0이 몇 개 들어가는 너비"): `.xlsx`와 그대로 맞는다. / 그릴 때마다 바꿔야 하고, 열 너비 px가 글꼴에 따라 달라진다.

## 결정
모두 A안이다. (사용자 선택)
- `Sheet`는 사용자가 직접 바꾼 행 높이·열 너비만 px로 갖는다. 기본 크기인 줄은 저장하지 않는다. 나중에 `toJSON`/`fromJSON` 하나로 셀과 크기를 함께 저장할 수 있다.
- 행·열을 넣고 지우면 `Sheet.changeStructure`가 셀과 함께 크기도 옮긴다. 지운 줄의 크기는 결과에 담아 `StructureCommand`의 undo가 되살린다.
- 자동 행 높이는 입력한 글자의 줄 수로 화면 쪽에서 계산하고 저장하지 않는다. 직접 높이를 바꾼 행은 자동으로 바뀌지 않는다. 경계선을 두 번 클릭하면 직접 바꾼 높이를 지워 다시 자동이 된다. (Excel과 같음)
- 결정 없이 정한 것 (Excel과 같게):
  - 열 경계선을 두 번 클릭하면 그 열의 모든 행을 재서 너비를 맞춘다.
  - 크기를 0으로 줄여 숨기는 기능은 없다. 가장 작은 크기에서 멈춘다.
  - 새로 넣은 행·열은 기본 크기로 시작한다. Excel은 위·왼쪽 줄의 크기를 따르는데, Step 10의 "서식이 위 줄을 따름"과 함께 맞춘다.

## 결과
- 저장할 문서 데이터가 `Sheet` 하나에 모인다. 불러올 때는 셀 글자에서 자동 높이를 바로 계산하므로 첫 화면부터 높이가 맞는다.
- 수식 결과에 든 줄바꿈은 한 줄로 보인다. Step 10의 "자동 줄바꿈" 서식을 켠 셀만 여러 줄로 그리면 Excel과 같아진다.
- `.xlsx`를 읽고 쓰게 되면 경계에서 단위를 바꾼다. (행 px × 0.75 = pt, 열은 기본 글꼴의 숫자 너비로 나눈다)
- 크기를 행 번호로 저장하므로, 나중에 실시간 협업에서 동시에 행을 넣으면 번호가 밀리는 문제가 있다. 셀 저장(ADR 0008)도 같은 문제라 그때 함께 다룬다.
