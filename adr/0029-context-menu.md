# 0029. 오른쪽 클릭 메뉴: 클립보드 접근과 코드 위치

- 상태: 채택
- 날짜: 2026-09-30
- 관련 Step: Step 7

## 배경
ADR 0026에서 행·열 넣기/지우기는 머리글 선택 + 단축키로만 하고 오른쪽 클릭 메뉴는 두지 않았다. Step 7에서 메뉴를 더한다.
메뉴의 잘라내기·복사·붙여넣기는 키보드 단축키와 달리 브라우저의 `copy`·`paste` 이벤트가 생기지 않는다. 클립보드를 직접 읽고 써야 하는데, 읽기는 브라우저 권한이 필요하다.
메뉴는 Docs·PPT에서도 쓸 수 있어서 코드를 어디에 둘지도 정해야 한다.

## 선택지
- 클립보드
  - A안 Clipboard API + 거부 시 안내: 쓰기는 `navigator.clipboard.writeText`(권한 창 없음), 읽기는 `readText`(처음 한 번 권한 창). 거부되면 "Ctrl+V를 쓰세요" 알림. / 권한 창이 한 번 뜬다.
  - B안 붙여넣기는 앱 안 복사만: 클립보드를 읽지 않고 기억해 둔 범위만 붙인다. / 밖에서 복사한 것을 못 붙이고, ADR 0025의 "글자가 같을 때만 수식째" 규칙과 어긋난다.
  - C안 붙여넣기는 안내만: 가장 단순 / 메뉴로 붙여넣기가 실제로 안 된다.
- 코드 위치
  - A안 `ui`에 React 없는 DOM 메뉴 + `excel`에 항목: GridView가 직접 연다. Docs·PPT도 같은 메뉴를 쓴다. / `excel`이 `ui`를 처음 import한다. (규칙상 허용)
  - B안 `ui`에 React 메뉴 + 앱이 그림: GridView는 "메뉴를 열어 달라"는 알림만 낸다. / 공개 인터페이스가 늘고 연결 코드가 `apps/web`에 생긴다.
  - C안 모두 `excel` 안: 가장 빠름 / Docs·PPT에서 다시 만들어야 한다.

## 결정
모두 A안이다. (사용자 선택)
- **클립보드:** 메뉴의 복사·잘라내기는 단축키와 같은 글자(ADR 0025)를 `writeText`로 넣는다. 붙여넣기는 `readText`로 읽어 단축키 붙여넣기와 같은 코드로 붙인다.
  - 읽기가 거부되거나 안 되면 아무것도 바꾸지 않고 "브라우저가 클립보드 읽기를 막았습니다. Ctrl+V(⌘V)를 쓰세요." 알림을 띄운다.
- **코드 위치:**
  - `@office/ui`의 `ContextMenu`: 항목 목록을 받아 화면 안에 들어오게 띄운다. ↑↓·Enter·Esc, 바깥 클릭·스크롤로 닫기, 흐린 항목 건너뛰기를 맡는다. React 없이 DOM만 쓴다.
  - `@office/excel`의 순수 함수: 어디를 눌렀는지(행 머리글·열 머리글·셀)와 선택, 시트 크기로 항목·글자("위에 행 3개 넣기")·흐림 여부를 정한다.
  - GridView가 `contextmenu` 이벤트, Shift+F10, 메뉴 키를 받아 메뉴를 열고 고른 동작을 실행한다.
- ADR 0026의 "조작"에 오른쪽 클릭 메뉴를 더한다. 0026의 나머지(시트 크기, 알림, undo)는 그대로다.
- 결정 없이 정한 것:
  - 오른쪽 클릭한 곳이 선택 안이면 선택을 두고, 밖이면 그 셀·줄을 고른 뒤 연다.
  - 셀 메뉴의 넣기/지우기는 고른 셀이 걸친 줄 전체에 한다. "아래에 넣기"·"오른쪽에 넣기" 뒤에도 선택은 원래 줄에 둔다. (구글 시트와 같음)
  - 입력 중에 입력창을 오른쪽 클릭하면 브라우저 기본 메뉴를 쓴다. 다른 곳을 오른쪽 클릭하면 왼쪽 클릭처럼 먼저 확정한다.
  - 단축키 표시는 Mac이면 ⌘X, 아니면 Ctrl+X 모양이다.
  - 시트를 비우게 되는 지우기와 최대 크기를 넘는 넣기는 흐리게 한다.

## 결과
- 메뉴 붙여넣기를 처음 쓸 때 브라우저가 권한을 묻는다. Safari·Firefox는 작은 "붙여넣기" 버튼을 띄운다.
- 브라우저 테스트는 Chromium에서 클립보드 권한을 주고 돈다. 권한 거부 알림도 따로 확인한다.
- `ContextMenu`는 DOM이 필요해 순수 계산(다음 항목 찾기, 화면 안 위치)만 단위 테스트하고 나머지는 브라우저 테스트로 본다.
- 구현하며 알게 된 것:
  - 입력창은 마우스 이벤트를 받지 않는다. (Step 3) 그래서 입력 중인 셀을 오른쪽 클릭하면 뜨는 것은 글자 복사·붙여넣기가 있는 입력창 메뉴가 아니라 페이지 메뉴다. 입력창 메뉴가 필요하면 입력 중에만 입력창이 마우스를 받게 바꿔야 한다.
  - Mac의 Ctrl+클릭은 왼쪽 클릭으로 처리하지 않고 오른쪽 클릭으로 본다.
  - 키보드로 열 때 활성 셀이 보이도록 스크롤했으면 다음 프레임에 연다. 바로 열면 뒤늦게 온 스크롤 이벤트에 메뉴가 닫힌다.
  - 전체 선택 뒤 "내용 지우기"는 10만 행 × 50열 예시에서 약 0.8초, undo는 약 1.1초 걸린다. (Delete 키와 같은 코드)
