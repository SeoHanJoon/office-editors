# 0007. undo/redo 기반: Command와 History

- 상태: 채택
- 날짜: 2026-09-30
- 관련 Step: Step 1

## 배경
Excel · Docs · PPT가 같은 방식으로 undo/redo를 쓰도록 `command-core`에 공통 기반을 만든다.
`command-core`는 셀·문서·슬라이드를 모른다. 편집 한 번을 쪽지(Command)로 만들어 기록 관리자(History)에 넘기면,
History가 실행하고 쌓아 두었다가 되돌린다. 쪽지의 모양, 연속 입력 합치기, 여러 편집 묶기, 기록 개수를 정해야 한다.

## 선택지
- Command 모양
  - A안 `execute()`와 `undo()`를 둘 다 적기: 읽기 쉽고 흔함, 같은 쪽지가 undo/redo 목록을 오가 추적 쉬움 / 되돌리기를 빠뜨리는 실수 가능
  - B안 `apply()`가 반대 쪽지를 돌려주기: 셀 입력처럼 "같은 동작, 다른 값"이면 짧고 실수가 적음 / 행 삭제(`=A5`가 `=#REF!`가 됨)처럼 반대 동작이 단순하지 않으면 복구용 쪽지를 따로 만들어야 함
  - (성능은 같다. undo/redo는 목록 맨 위만 보고, 메모리 차이는 셀 10만 개 편집에서 1MB 미만)
- 연속 입력 합치기
  - A안 History가 묶음으로 합침(`mergeKey` + 시간 간격): 쪽지마다 합치는 코드가 필요 없음 / 묶음 안 쪽지를 모두 들고 있음
  - B안 쪽지가 `mergeWith()`로 하나로 합침: 메모리 적음 / 쪽지 종류마다 합치는 코드 필요
- 여러 편집 한 번에 되돌리기
  - A안 `batch(콜백)`: 앞 편집 결과를 보고 다음 편집을 정할 수 있고, 에러 시 자동으로 없던 일로 / 콜백 모양
  - B안 묶음 쪽지를 직접 만들기: 단순 / 실행 전에 쪽지를 전부 알아야 함 (Step 5 행 삽입에 불편)
  - C안 `begin()`/`end()`: 익숙함 / `end()`를 놓치면 이후 편집이 전부 한 묶음이 됨
- 기록 개수: 기본 100개(설정 가능) / 제한 없음(오래 편집하면 메모리가 계속 늘어남)

## 결정
- Command는 A안 `{ execute(); undo(); mergeKey? }`. 행 삭제 같은 편집도 같은 방식으로 쓰고, 문제가 생겼을 때 추적하기 쉽다.
- 합치기는 A안. `mergeKey`가 같고 직전 편집에서 0.5초(`mergeWindowMs`) 안이면 같은 묶음에 넣는다. undo·redo·batch 뒤에는 끊는다.
- 묶기는 A안 `history.batch(fn)`. 중첩하면 바깥 하나로 묶이고, 에러가 나면 그 batch에서 한 편집만 되돌리고 다시 던진다.
- 기록은 기본 100개(Excel 기본값), `new History({ limit })`로 바꾼다. 넘으면 가장 오래된 것부터 버린다.

## 결과
- 에디터는 편집마다 Command를 만들고 `history.execute()`로만 바꾼다. 데이터를 직접 고치면 undo가 깨진다.
- 되돌리기 실수는 Command마다 "실행 → undo 하면 처음 상태와 같은지" 테스트로 잡아야 한다.
- execute가 에러를 던지면 아무것도 바꾸지 않았다고 본다. 반쯤 바꾸고 실패하면 History가 복구하지 못한다.
- batch 안에서는 undo/redo를 부를 수 없고, `fn`은 동기 함수여야 한다.
- 화면(undo 버튼 활성화 등)에 알리는 기능은 아직 없다. 화면을 붙이는 Step에서 필요하면 추가한다.
- 클래스 이름 `History`는 브라우저의 `window.History` 타입과 이름이 같다. 가져다 쓰는 파일 안에서는 가져온 것이 우선한다.
