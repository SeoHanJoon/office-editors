# 0024. 처음 열기: 표를 먼저 그리고 수식은 나눠서 계산

- 상태: 채택
- 날짜: 2026-09-30
- 관련 Step: Step 5

## 배경
`/excel`을 10만 행 성적표로 키운 뒤(ADR 0023) 페이지 열기가 `main`의 0.06~0.2초에서 2.2~3.0초로 늘었다. 그동안 화면은 하얗게 멈춰 있었다.
시간은 거의 다 수식 엔진이 처음에 수식 20만 개를 한 번에 계산하는 데 쓰였다. 시트를 만드는 데는 0.1초면 된다.
사용자 목표: **셀까지 그려진 첫 화면을 0.5초 안에** 보여준다.

## 선택지
- 1안 처음 열기 경로 다듬기 (구조 유지): 전체 시간이 줄어듦 / 여전히 그동안 화면이 멈춤
- 2안 표를 먼저 그리고 수식은 조금씩 나눠 계산: 화면이 바로 뜨고 멈추지 않음 / 수식 칸이 잠시 비어 있고, 엔진 인터페이스가 늘어남
- 3안 Web Worker(다른 스레드)에서 계산: 메인 스레드가 전혀 멈추지 않음 / 시트 복사·메시지·비동기 편집까지 구조가 크게 바뀜
- 4안 예시 시트를 가볍게: 문제를 가릴 뿐 엔진은 그대로

세부 선택
- 첫 화면에 보일 것: 입력값 + 보이는 칸 중 값만 참조하는 수식 / 입력값만
- 계산 안 된 칸 표시: 빈 칸 + 위쪽에 "계산 중" / 칸에 회색 "…" / 둘 다
- 인터페이스: 생성자 옵션 `{ background: true }` / 별도 함수 `FormulaEngine.loadInBackground`
- 계산 중 편집: 남은 계산을 끝내고 반영 / 편집을 계산 대기열에 합치기

## 결정
1안 + 2안. 첫 화면에는 입력값과, 보이는 칸 중 값만 참조하는 수식을 보여준다. 계산 안 된 칸에는 회색 "…"를 그린다. 인터페이스는 생성자 옵션으로 하고, 계산 중에 편집하면 남은 계산을 끝낸 뒤 반영한다.
- `new FormulaEngine(sheet, { background: true })`: 처음 읽기·연결 찾기·계산을 제너레이터로 써서 `setTimeout` 한 번에 8ms씩 진행한다. 계산된 수식 셀은 `onChange`로 알리고, 다 끝나면 `calculating`이 false가 된다. 옵션이 없으면 지금처럼 한 번에 계산한다. (테스트·bench는 그대로)
- 계산 중에 화면이 셀을 물으면(`getValue`, `isPending`) 그 수식이 참조하는 셀이 모두 정해져 있을 때만 그 자리에서 계산한다. 보이는 행의 `=SUM(D2:F2)`는 바로 나오고, 총점 10만 개를 기다리는 `=SUM(G2:G100000)`은 "…"로 남는다. 참조한 수식을 따라 더 들어가지 않아서 오래 걸리지 않고, 순환에 걸린 셀은 늘 "…"이다.
- 계산 중에 시트가 바뀌면(편집, undo) 남은 계산을 한 번에 끝낸 뒤 바뀐 셀을 반영한다. 처음 1~2초 안에 편집할 때만 잠깐 멈출 수 있다.
- GridView는 `engine.onChange`를 듣고 다시 그린다. (ADR 0020에서 "필요해지면 더한다"고 한 것)
- 1안으로 함께 바꾼 것: 값 셀은 처음 열 때 해석하지 않고, 수식이 읽을 때 해석해 기억한다. 화면에 그리려고 읽을 때는 기억하지 않는다. 스크롤 중에 큰 Map이 커지다가 한꺼번에 자리를 옮기며 프레임이 밀리는 것을 막기 위해서다.

## 결과
- 브라우저(개발 서버) 기준: 첫 화면 **0.23~0.40초**, 수식 계산 완료 1.4~1.85초. (`main`의 1,000행 시트는 0.06~0.2초) 그동안에도 스크롤할 수 있다.
- 엔진만 재면 처음 계산이 성적표 1.26초 → 1.03초, 500만 칸 시트 2.43초 → 0.56초로 줄었다.
- 대신 셀 수정은 조금 느려졌다. 성적표 셀 수정은 2.4ms → 5.2ms, 큰 `SUM` 시트 수정은 3.5ms → 4.4ms로, 목표 16ms 안이다. 값이 계산 순서대로 Map에 들어가는 탓으로 짐작했지만, 넣는 순서를 바꿔 봐도 빨라지지 않아 원인을 찾지 못했다.
- `getValue`는 계산 중인 셀에 null을 돌려준다. 빈 셀과 구분하려면 `isPending`을 쓴다.
- 브라우저 테스트는 `window.__excel.state().calculating`이 false가 될 때까지 기다린 뒤 시작한다. 처음 열기 동작은 따로 한 테스트에서 확인한다.
- Chrome 성능 기록(ADR 0022의 ②)은 한 프레임에 기록이 둘 붙기도 해서, 프레임 번호별로 묶어 센다.
